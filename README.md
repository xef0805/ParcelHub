# 涂涂取件 ParcelHub

个人自用的 iOS 取件助手。已接入本人登录后的淘宝官方待取清单，保留兔喜生活、驿收发和丰巢的小程序入口，并支持手动导入短信作为本机取件凭证。

## 0.7.5 开发版

- 修复取完件后淘宝手机号空页面被永久当成异常、旧包裹不能移出主页的问题。同一页面连续两次独立读取确认空清单后，自动更新淘宝来源的待取状态。
- 确认过程不复用同一缓存快照；加载、登录、网络错误或矛盾卡片会中断确认。其他来源的包裹、短信原文和已有历史继续保留，不根据消失自动编造取件时间。
- 精简同步、导入、绑定和设置说明；身份码页移除排序区，改用一行轻提示。更新时间以时钟图标和时分紧凑显示，旧日期再补月日；历史排序数据保留。
- 当前为 0.7.5/build 12。67 项 Node 测试、6 项 Python 测试通过；原生确认流程仍待编译和 iPhone 验证。

## 0.7.0 开发版

- 首页数量卡下增加一行“运单号导入 / 手动导入包裹”。单号支持粘贴、快递公司提示和选填名称，导入后单独展示在“待到站”，不计入已到站待取数量，不生成取件码。
- 同运单已存在时提示并关联原记录；淘宝清单读取到完整取件信息或补充取件短信后，沿用原记录移入待取清单。空官方清单不删除待到站记录。
- 进入或回到 App 前台时检查变化后的剪贴板，识别单号或取件短信后提示“去导入”；确认后预填对应表单，不直接保存。设置可关闭检测，iOS 的粘贴权限仍由用户决定。
- **尚未接通各家物流的自动轨迹查询接口。** 当前“官方查询”会复制单号并打开菜鸟官方网页，需用户粘贴查询；没有在 iPhone 验证该网页的完整查询流程。要实现菜鸟式全网跟踪，仍需可用的查询服务授权。
- 修正已取记录滑动按钮受全局自定义按钮样式影响的问题，重复包裹增加明确提示；短信凭证改为全屏会话、左上返回，移除说明小字和“完成”；驿收发改用官方小程序的 640 × 640 原图。

本地共享逻辑与网页交互验证见 [验证记录](docs/VALIDATION.md)。Windows 未运行 Xcode；原生右滑删除、剪贴板系统权限及新界面仍需编译后在 iPhone 验收。

## 能力与限制

用户已在 0.2.0 iPhone 版本确认淘宝网页登录、身份码显示及待取件读取可用。0.3.0 的视觉和真机行为需要安装新版后再次验收，不能用旧版反馈代替新版验证。

0.6 仅保留四个官方平台与本机短信凭证。仅淘宝网页接入 App 内身份码展示与清单读取，其他三个小程序的首页链接已核实，但没有接通其动态码或自动汇总。不会把淘宝码当成其他平台身份码，也不会根据快递公司自动猜测驿站支持的凭证。

现场微信小程序码可能携带站点信息，需按现场说明用微信扫一扫。首页跳转链接不等于身份码页链接，也不等于能够读取包裹数据。普通二维码读取器不能直接解析微信小程序码。

取件状态不会在后台实时刷新；可回到 App 前台或下拉主页清单检查。官方记录不再出现时只移出该来源的待取状态，不据此伪造“已取件”历史。动态身份码由官方服务生成和刷新，不复制、缓存或重画条形码；短信凭证展示用户导入的原文。

## Windows 编译与安装

详细步骤见 [手动编译与更新](docs/BUILDING.md)。

打开 GitHub 仓库 Actions，手动运行 Build iPhone test package (unsigned)，分支选择 main。流程先运行 JS 与原生 Swift 数据同步检查，再编译并上传 ParcelHub-unsigned-iphone，产物保留 3 天。

使用 iLoader 的 Import IPA 给自己的 iPhone 签名安装。更新时沿用之前的账号和 Bundle ID 设置，尽量覆盖安装；不要先删除旧 App，以免清除本地记录。免费签名需要定期续签，安装工具和 Apple 账号验证由用户自行完成。

## 数据与来源

.private/ 保存仅本机的真实快照，已忽略，不上传到 GitHub。测试使用虚构包裹，不包含真实姓名、手机号、取件码或运单。App 使用 WebKit 的持久会话完成官方登录，不提取或上传 Cookie、密码和登录令牌。

原先参考 PickTool、BiuLand、fluwx 与 ExpressAssistant 的架构思路，未复制其源码或品牌素材。当前不调用逆向接口，不绕过验证码、权限或访问控制。
