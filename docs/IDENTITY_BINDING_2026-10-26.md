# 小程序入口绑定验证

本轮目标是先验证首次绑定后能否打开对应小程序；小程序首页、身份码页面和读取身份码是三种不同能力。源码上传后需用户手动触发编译，当前尚无本版原生构建与真机验收结果。

## 兔喜的实际证据

用户先提供 `#小程序://兔喜生活/…` 分享口令；它不是已验证的外部 Scheme，本项目不尝试用口令尾部猜测票据。

随后用户从“添加到桌面”提供 [微信官方桌面链接](https://wxmpurl.cn/3VHyC8pPJcq)。2026-10-26 实际 HTTP 请求得到 200。网页公开配置中的昵称是“兔喜生活”，原始标识为 `gh_2ab5c6580f27`，页面路径与查询均为空，并包含 `weixin://dl/business/?t=…` 跳转票据。这支持“指向兔喜首页”的结论，不能据此声称直达身份码或有数据查询权限。网页同时带有示例配置，解析器必须排除示例，核对真实昵称再读取票据。

兔喜与拼多多保留独立入口。[中通官网的兔喜页面](https://www.zto.com/introduce/service/tuxi)及[兔喜官网](https://tuxi.zto.cn/)可确认中通体系关联；[拼多多官方应用条目](https://apps.apple.com/cn/app/id1044283059)发布者为上海寻梦，当前未找到可证明双方身份码通用的官方依据。

## 本地实现

1. 兔喜预填已核实的官方桌面链接。其他平台可粘贴自己的完整官方链接或分享口令；首次试开并人工确认目标，不自动将“系统接受打开请求”视作小程序成功进入。
2. 原生使用不持久保存 Cookie 的临时网络会话读取官方短链接页；核对响应与最终 URL，读取公开票据而不执行网页脚本，再交给系统打开微信。
3. 确认后的绑定保存原始官方链接。以后从身份码卡片、常用入口或已绑定地点点击，重新解析当前公开票据并尝试打开，不再先弹绑定窗口。
4. 网络、页面格式或目标核对失败时返回绑定界面，可重新获取链接或在 Safari 打开官方入口。分享口令只保存为口令，并明确仍需在微信内打开。
5. 在“我的 → 设置 → 小程序入口绑定”或长按身份码行管理绑定；右滑删除平台入口会清理其入口、常用与地点绑定，保留全部包裹与已取历史。

当前接收微信官方短链接域名 `wxmpurl.cn`、`wxaurl.cn`，或完整的 `weixin://dl/business/?t=…`。没有调用私有接口、提取账号凭证、接入未注册 SDK 或编造平台 AppID。

## 验证范围与待验收

- 本地共享解析测试覆盖口令/外链区分、错平台、示例配置、无效页面、不执行脚本和恶意地址；实际官方页也已通过共享解析器的目标核对。
- 会话内网页预览验证整行点击、右滑删除、重新添加、拖动并保存排序、短信识别、新名称、缺失字段提示、历史分组和搜索。
- Windows 不能完成 Xcode 构建或 iPhone 的微信切换。原生首次试开、返回确认、再次直开、失效时重绑仍需新版真机验收。未核实链接有效期，不承诺永久可用。
- 兔喜、拼多多等小程序中的全部待取清单和身份码本身仍由官方服务提供，本轮没有新增这些平台的数据同步。

真机步骤：身份码 → 兔喜 → 试开兔喜生活 → 检查是否进入正确小程序 → 返回涂涂取件 → 确认并保存 → 再点击兔喜卡片或绑定地点。若只出现微信首页、报错或错误小程序，不要确认绑定。
