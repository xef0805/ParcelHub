## 0.7.4 本地读取与重登修复（2026-10-30，未发布）

- 用户反馈 0.7.3 首页缺新包裹，内嵌官方网页也缺新包裹，并显示“官方清单仍在加载，保留原有记录”；用户进一步确认新件已到站待取。随后截图显示官方“未查到当前手机号的包裹”。用户已确认收件手机号相同，在淘宝 App 打开相同页面能看到新件；排除号码不一致，尚未确认网页会话或网页渠道为何缺件，不能把本地修复视作该账号已恢复同步。
- 当日无登录请求检查：现有淘宝待取入口 HTTP 200，实际引用的 `m-end-school-tab/0.0.152/js/p_home-index.js` 与 `main.js` 均 HTTP 200。公开脚本的商品推荐组件会显示“加载中”。这只证明页面和脚本可访问，不证明用户清单接口成功、账号有效或数据最新。
- 已复现读取器误判：完整非空清单后附加推荐“加载中”时，旧实现返回 loading。修复后，只有通过地点、运单、取件码及数量完整校验的非空清单可忽略该文案；零件占位、残缺卡片、错误和登录状态仍不能清空本地记录。

- 公开主脚本的请求适配器先检测客户端 MTOP/requestData 能力，可用时走客户端桥接，否则回退到 lib.mtop 网页请求；这证明宿主环境存在不同请求路径，不能据此认定当前账号被限制。用户已进一步确认 Safari 的同账号网页能看到最新待取件，问题范围缩小到涂涂取件内的网页会话、缓存或 WebKit 环境，尚未证明具体原因。
- 原“重新登录”实际只重载清单，现增加用户确认后的官方退出→登录→返回流程。入口和 redirectURL 参数来自该页实际引用的公开 `lib-login/1.6.4/login.js`，不读取或迁移 Safari、淘宝 App 的 Cookie，不伪装淘宝客户端。登录时暂停自动清单请求并卸载隐藏旧页面，关闭登录容器后恢复前台策略。
- 增加 filtered_empty 状态，提示核对网页账号并用浏览器打开比较，不将相同手机号自动视作相同登录会话。按手机号空结果不再反复重试，不输出或保存选中号码，也不会作为完整空快照清空其他包裹；原生与预览均传递此状态。测试使用虚构号码，未把用户截图加入项目。
- 新增回归用例先失败、修复后通过。64 项 Node 测试、4 项 Python 测试及差异空白检查通过。Swift 源码增加官方重登 URL 编码、目标域名与非完整清单保护用例，Windows 未运行 Swift/Xcode；官方退出登录实际跳转、暂停自动刷新和重登后新包裹恢复仍待 iPhone 验收。未上传、未云端编译，版本为 0.7.4/build 11。
